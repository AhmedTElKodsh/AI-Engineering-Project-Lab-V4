# Lesson and interaction template

Use the shape that matches the request. Do not mechanically include every section in a two-line answer.

## First exposure

1. Product limitation: what cannot the current mini-release do?
2. Mental model: smallest sketch/analogy plus where it breaks.
3. Mechanism: exact inputs, outputs, owner, trust boundary, and failure surface.
4. Runnable action: one change or inspection that produces visible output.
5. Prediction: only after enough explanation exists.
6. Evidence: compare expected versus observed.
7. Close: capture the result and name the next limitation, not a large backlog.

## Debug

Expected -> observed -> failing layer -> one discriminating hypothesis -> smallest experiment -> correction -> regression evidence.

## Assess

State the bounded task and allowed resources. Do not reveal the answer. Use a genuinely different case from the worked example. On help request, switch to Learn/Build together and record assistance rather than pretending independence.

## Build together

Confirm the scoped change, provide the requested help, run/request the focused check, then record what the assistant supplied. Independent evidence later must come from a different task.

## Stage-end capture

A closed mini-release has: bounded purpose, reproducible run, expected-behavior checks, known limitations, and at least one ownership observation. Save artifacts while fresh.
