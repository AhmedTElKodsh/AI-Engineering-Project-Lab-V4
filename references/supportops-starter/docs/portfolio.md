# Portfolio evidence

The initial featured project is **one SupportOps AI application**. A second required domain project is not part of this route.

Capture evidence during the build: a working J1 intake with one known failure; J3 cited answer plus abstention/retrieval miss; J4 allowed lookup, blocked wrong-scope lookup, and rejected/changed proposal with zero effect; J5 reproducible run, evaluation summary, limitations, learner contribution, and independent change/debug record.

Use honest maturity labels:

- **Learning build:** small runnable slice with a few expected-vs-observed cases and known limitations.
- **Demonstrable engineered project:** reproducible interface, focused boundary checks, held-out evaluation, independent modification/debugging, readable README.
- **Operational system:** deployment, access controls, monitoring, load/recovery/cost/rollback evidence for the actual environment.

Do not label B as C merely because Docker or many tests exist. Applications may begin when a role's must-haves are genuinely covered; route completion is not a universal job-readiness certificate.

Add brief technical-interview preparation from the project: explain a boundary, diagnose a trace, modify SQL/Python, and defend one design trade-off. Add broader interview branches based on current target roles rather than assuming the project covers every interview format.
