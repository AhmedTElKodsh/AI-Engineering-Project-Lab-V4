# Product-learning backlog

This backlog is grouped by the canonical J0-J5 stages. It is planning detail, **not a second progress-ID system**. Progress is recorded only through the J/E/Q schema under `progress/`.

## J0 — Reply Drafter

- Reconcile the learner app location/environment and current provider documentation.
- Make one authorized provider call using synthetic message + supplied policy.
- Inspect response shape and create a human-review draft.
- Add the smallest local failure handling needed for the observed boundary.

## J1 — Ticket Intake

- Define a small Pydantic case schema.
- Handle missing fields, negation, uncertainty and instruction-like customer text.
- Attach original-text evidence spans using the code-point coordinate contract.
- Add focused repeatable checks using the frozen support fixtures.

## J2 — Transfer

- Adapt the intake mechanism to a delivery dispute with conflicting attributed records.
- Preserve source identity/uncertainty and demonstrate learner-owned modification/explanation.

## J3 — Policy retrieval

- Build a lexical/exact-term baseline.
- Choose one currently documented embedding route and compare it on the same labeled questions.
- Preserve document/version/section/chunk provenance.
- Close a search-only Policy Finder.
- Add generation only after retrieval is inspectable; support citations/abstention/conflicting evidence.

## J4 — Operational facts and controlled action

- Create a small synthetic order store and parameterized scoped lookup.
- Keep trusted actor/tenant identity outside model-controlled arguments.
- Expose narrow read tools through a bounded native tool loop.
- Add deterministic eligibility.
- Create an immutable replacement proposal and exact approval transition.
- Execute one local simulated effect with execution-time rechecks and replay prevention.

## J5 — Delivery and ownership

- Make one coherent SupportOps flow reproducible for another person.
- Assemble held-out evaluation/failure analysis without inventing significance.
- Keep model-quality evaluation separate from deterministic software checks.
- Capture one independent learner change, debug and transfer plus architecture defense.
- Prepare README/demo/limitations/assistance disclosure and current role-gap notes.
