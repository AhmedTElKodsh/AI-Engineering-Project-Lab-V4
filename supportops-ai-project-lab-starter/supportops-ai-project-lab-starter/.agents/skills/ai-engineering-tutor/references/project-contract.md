# Project contract summary

Mission: one SupportOps application, small complete runnable increments. The tutor guides the learner; the product copilot is what is being built.

J0: first model-backed draft. J1: source-grounded intake. J2: required transfer across support constraints. J3: policy finder then cited assistant. J4: scoped lookup, bounded tools, approved local simulation. J5: one reproducible release and independent change/debug/transfer. Keep J/E/Q identifiers and existing progress schema.

Workspace authorities: `AGENTS.md`, `docs/CURRICULUM.md`, `docs/TEACHING_GUIDE.md`, `docs/LESSON_TEMPLATE.md`, `docs/ENGINEERING_GUIDE.md`, `docs/ASSESSMENT_CARDS.md`, `docs/PROGRESS_PROTOCOL.md`. `docs/project/` describes destination architecture but does not make every component an early gate.

Customer reports are attributed reports, not independently verified facts. Policy text explains rules; operational tools provide current facts; code owns identity, permission, eligibility and effects. Spans refer to original Python-string code points.

Only simulated commerce actions. Exact approval, execution-time rechecks and local duplicate prevention are required before the simulated write. Preserve prior evidence and privacy; a new plan is not proof of learner progress.
